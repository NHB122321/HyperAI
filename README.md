# HyperAI

Персональный агент Джонни: Telegram, голос, память, криптовалютные цены и учёт финансов. Выбирает модель через `ModelRouter`, а существующие инструменты выполняет через Responses API.

## Модели и режимы

| Режим | Поведение |
| --- | --- |
| `auto` | Выбор по правилам: обычные запросы → быстрая модель; анализ, сравнение, планирование, работа с кодом, несколько шагов или большой текст → сильная. |
| `fast` | Всегда `FAST_MODEL`; по умолчанию `gpt-5.6-luna`. |
| `smart` | Всегда `SMART_MODEL`; по умолчанию `gpt-6-astra`. |

В Telegram: `/auto`, `/fast`, `/smart`, `/mode`. Переключение сохраняет историю. Режим относится к конкретному чату и действует до следующего переключения или перезапуска бота. `/reset` очищает диалог и текст для уточнений, сохраняя выбранный режим.

Примеры для `auto`:

| Запрос | Выбор |
| --- | --- |
| «Привет» | fast |
| «Я потратил 300 лей на продукты» | fast |
| «Какая цена BTC?» | fast |
| «Покажи сводку за сегодня» | fast |
| «Проанализируй мои расходы за 3 месяца» | smart |
| «Составь план обучения Python» | smart |
| «Разбери этот код» | smart |
| «Сравни несколько новостей и сделай вывод» | smart |

Маршрутизатор выбирает модель; он не добавляет источники новостей, новые финансовые отчёты или другие инструменты. Доступные действия по-прежнему определяет текущий набор функций проекта. «Продолжи» и «Подробнее» учитывают последний самостоятельный запрос; новый запрос вроде «Какая цена BTC?» оценивается заново.

## Настройка и запуск

Нужен Python 3.10 или новее. Команды выполняются из папки проекта.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для новой установки скопируй `.env.example` в `.env` и заполни свои ключи и Telegram ID локально. Для существующего проекта сохрани прежние ключи и `DATA_DIR`, добавив при необходимости только настройки моделей:

```dotenv
FAST_MODEL=gpt-5.6-luna
SMART_MODEL=gpt-6-astra
MODEL_MODE=auto
TRANSCRIPTION_MODEL=gpt-transcribe
```

`config.py` читает `.env` рядом с собой. Уже установленные переменные окружения имеют приоритет. Пустое имя модели или неизвестный режим вызывают понятную ошибку при запуске. После изменения настроек перезапусти бот.

```powershell
.\.venv\Scripts\python.exe telegram_bot.py
```

Консольная версия: `.\.venv\Scripts\python.exe main.py`. Она тоже поддерживает `/auto`, `/fast`, `/smart`, `/mode`; для завершения введи `выход`.

При переносе рабочего бота сохрани его существующие `.env`, `finance.db`, `memory.json` и путь `DATA_DIR`. Репозиторий не содержит эти личные данные. Запускай один экземпляр Telegram-бота с данным токеном.

## Что изменено

- `config.py`: имена моделей и стартовый режим из окружения; `MODEL` оставлен как совместимое имя для `FAST_MODEL`.
- `model_router.py`: выбор модели и объяснение причины без отдельного API-запроса.
- `HyperAI.py`: модель выбирается один раз на сообщение и используется до завершения всех инструментов. Консоль использует тот же цикл; старый дублирующий цикл удалён.
- `telegram_bot.py`: режимы по чатам, сохранение истории и исходной задачи для уточнений. Ожидание API перенесено в рабочий поток, длинные ответы разбиваются на части, пустой ответ явно обозначается.
- `voice_tools.py`: имя модели распознавания взято из конфигурации; транскрипт проходит через общий маршрутизатор.
- `logger.py`: строка `MODEL` в `agent.log` содержит режим, модель и причину выбора.

Старые команды, кнопки, инструкции агента и реализации финансовых функций, криптовалютных запросов и памяти сохранены. Проверка доступа теперь также выполняется до распознавания голоса, сброса истории и показа справки.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют выбор модели, ручные режимы, продолжения, историю, команды, кнопки, голос и цикл инструментов. Для финансов и памяти используются настоящие временные SQLite/JSON-файлы. Ответы OpenAI и Telegram имитируются: ключи и сетевые запросы для этих проверок не нужны.

Проверки не подтверждают доступ конкретного API-ключа к моделям и качество их реальных ответов. Для проверки после запуска: отправь `/auto` и простой вопрос, затем запрос на анализ; посмотри строки `MODEL` в журнале. Проверь `/fast`, `/smart`, `/mode`, переключение без потери диалога и голосовое сообщение. Если модель недоступна аккаунту, исправь её имя в `.env` или выбери доступный режим. Автоматическая повторная обработка другой моделью не добавлена: она могла бы повторно записать уже выполненную финансовую операцию.

Правила маршрутизации приблизительные: некоторые формулировки могут быть оценены неверно. Ручные режимы позволяют поправить выбор. Режимы и история остаются в памяти процесса, как история в исходном боте.

## Разбор для Артёма

[Пошаговое объяснение новых блоков](docs/model-routing.md) связывает код с путём сообщения от Telegram до ответа и содержит небольшие упражнения.

Названия и поддержку вызова функций проверяли по официальной документации: [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna), [GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra). История использует [previous_response_id](https://developers.openai.com/api/docs/guides/conversation-state).
